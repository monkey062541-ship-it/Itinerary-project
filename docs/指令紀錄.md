### 12. Webhook 驗證回傳 405

> webhook 回傳的 HTTP 狀態碼不是 200。（405 方法不允許）

**處理**：非程式問題。Webhook URL 少了結尾的 `/callback`。

應用程式有兩個路徑，用途不同：

| 路徑 | 方法 | 用途 |
|---|---|---|
| `/` | GET | 健康檢查 |
| `/callback` | POST | LINE 平台送訊息的入口 |

LINE 以 POST 呼叫 webhook，打到只收 GET 的 `/` 就得到 405。
回傳 405 而非 404 反而代表服務正常運作、網址正確，只是路徑指錯。

正確填法：`https://<服務名>.onrender.com/callback`（結尾不要多加斜線）。
此設定即時生效，不需重新部署。

---

### 13. Webhook 驗證回傳 400 → 排除後成功

> webhook 回傳的 HTTP 狀態碼不是 200。（400 錯誤請求）

**處理**：405 改正路徑後變成 400，代表 LINE 已經連到伺服器，
問題轉為**簽章驗證失敗**（`InvalidSignatureError`），即 Render 上的
`LINE_CHANNEL_SECRET` 與 channel 實際的 Channel secret 不一致。

程式面補強：

- `app/config.py`：讀取憑證時加上 `.strip()`，避免複製貼上多帶空白或換行
- `app/main.py`：簽章失敗的 log 直接指出要核對哪一個設定

常見混淆點：Channel **secret** 在 **Basic settings** 分頁，
Channel **access token** 在 **Messaging API** 分頁，兩者位置不同。

**結果**：核對 secret 後 Verify 成功，webhook 串接完成。

### 14. 只回應關鍵詞，其餘保持安靜

> 只有在我問特定關鍵詞的時候提供回應，其他我跟別人對話都不要回

**處理**：把「認不出來就回『看不懂😅』」改成完全不回應。

- `reply_for()` 回傳型別改為 `str | None`，`None` 代表不回應
- 移除「看不懂」的 fallback
- `app/main.py` 收到 `None` 就直接 return，不呼叫 LINE API
- 說明關鍵詞獨立成 `HELP_WORDS`，並移除原本的空字串條件
  （否則像「的」這種被正規化成空字串的閒聊也會觸發說明）

**會回應的關鍵詞**：今天／明天／後天／本週／下週／最近／全部行程、
指定日期（`8/20`、`8月20日`、`2026-08-20`）、說明／功能／指令／選單／行程、
以及打招呼（哈囉／嗨／安安／你好／hello／hi／hey）。

其餘一律安靜。已針對「幫我訂機票」「晚上要吃什麼」「明天記得帶傘」
「ok」「👍」等一般對話驗證不會被誤觸發。
